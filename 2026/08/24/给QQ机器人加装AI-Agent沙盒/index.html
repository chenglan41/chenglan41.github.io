给QQ机器人加装AI Agent沙盒（工具调用自动续问）

Posted on 2026-08-24 Edited on 2026-08-25 In Coding

我的 QQ 机器人（Napcat + Deepseek 方案）原本只能”动嘴”聊天，遇到要算数、查文件、跑命令的活儿就只能干瞪眼。这次给它装上了”手”——一个 AI Agent 沙盒：node-pty 虚拟终端 + 沙盒文件系统，并且把询问器改成了”多轮循环”，AI 调用工具后会自动把结果发回去继续思考，直到给出最终回答。

一、核心改动：Agent 多轮循环

旧逻辑：AI 返回 tool_calls → 执行一次 → 直接回复。这样 AI 只能”一步到位”，一旦需要根据工具结果继续操作就抓瞎。

新逻辑（index.js 询问器重写）：

  1. 用户发消息 → 组装 prompt 发给 AI
  2. AI 返回 tool_calls → 自动执行全部工具，把结果作为 tool 消息发回
  3. AI 根据结果继续思考：可能再调工具，也可能给出最终回答
  4. 无 tool_calls → 回复用户，循环结束
  5. 兜底：单条消息最多循环 10 轮（MAX_AGENT_ROUNDS），防止 AI 无限调用

这样 AI 就能”边做边想”：先建文件夹，再写文件，再用终端看看目录，一气呵成。

二、14 个 Agent 沙盒工具

终端（虚拟 cmd.exe，node-pty 实现）

工具 说明
createProcess 创建虚拟终端，返回 id/pid/uid/workdir
removeProcess 关闭终端
inputProcess 向终端输入命令（自动回车）
outputProcess 读取终端输出（读后清空）

文件系统（沙盒内）

工具 说明
createFile / createFolder 创建文件 / 文件夹
deleteFile / deleteFolder 删除文件 / 文件夹
getFileInfo / getFolderInfo 查看文件 / 文件夹状态
listDir 列出目录内容
readFileContent / writeFileContent 读取 / 写入文件

辅助

工具 说明
agentHelp 获取整套工具的使用说明

工具以 Deepseek tool calls 格式注入 lib/tools.js，AI 按需调用，热更新即改即用。

三、沙盒安全机制

  • 每个会话独立沙盒目录 data/{uid}/，文件操作拒绝绝对路径与 .. 穿越
  • 危险命令黑名单：shutdown / format / reg / net / taskkill / curl 等，执行前先去掉 ^ 转义符防绕过
  • 配额限制：总空间 100MB、终端缓冲 300KB、单文件读取 200KB

四、部署（Windows）

cd /d C:/Users/Administrator/Desktop/QQ-bot
npm install
netstat -ano | findstr :8082   # 端口被占用时
taskkill /f /pid 9496          # 杀掉旧 bot
node .                         # 启动

五、踩坑记录

  1. 端口占用：8082 被旧 bot 进程占用导致 EADDRINUSE，杀掉旧进程或临时改端口即可。
  2. node-pty AttachConsole failed：Windows conpty 的无害警告，实测终端功能完全正常，不用管。

六、总结

现在机器人在群里说一句”帮我建个文件夹写点东西”，它就能自己开终端、建文件、查目录，把结果汇报给你。”工具调用自动续问”这个机制，让机器人的”动手”能力真正闭环了。全程只加了一个依赖 node-pty，改动集中在 index.js 与 lib 目录，热更新即改即用，推荐给所有玩 Napcat + Deepseek 的小伙伴。
